# AGENTS.md — Send Network Vault

You are reading the agent instructions for a **Send Network** church-planting vault, built from the Send Network Second Brain Starter Kit.

This is the shared team vault: the operational brain for the church-planting work. It holds planters, pastors, churches, events, team context, church mobilization, and Send-authored tasks. If you are an AI assistant working here, read this first.

Operate as the **team-facing agent**. This vault is shared with the church-planting team, so it may contain sensitive ministry operations, but keep private journaling, private pastoral interpretation, personal/family content, and any one leader's private material out of it.

Keep this file named `AGENTS.md`; agents auto-discover that filename.

## What this vault is

A shared knowledge base for the team to track and care for planters, mobilize churches toward planting, and run the network together. Keep the spheres of ministry distinct: Send Network people, churches, events, and pathway tracking live here. Anything private to one leader belongs in that leader's own separate, private vault, not here.

## The structure

- **`wiki/people/`** — one note per person, kept **flat**. Every person has a primary `person_type`; use `planter`, `pastor`, `staff`, `association_leader`, or `partner`. If the person fits multiple categories, keep the primary lane in `person_type:` for dashboards and put every true category in `person_types:`.
  - `person_type:` = one primary lane for compatibility with indexes/dashboards.
  - `person_types:` = multi-select list. Controlled values: `staff`, `pastor`, `planter`, `association_leader`, `partner`.
  - **Planters** carry `planter_pathway` (`funded` / `candidate` / `potential` / `aged-out`), `field_staff` (their CPC), and `sending_church`.
  - **Pastors** carry the `church` they lead.
  - **Staff** carry `staff_role` (`SCM` / `CPC` / `Assessment` / `Training` / `Spouse Care`) and `job_title`.
  - **Association leaders / partners** carry `association`, `organization`, `role`, and the relationship lane they affect.
- **`wiki/churches/`** — one note per church. Each carries `pastor` / `pastors`, `mobilization_level` (1–5, see below), `planters_sent`, `church_type`, and `association`.
- **`wiki/events/`** — Send Network events. Evergreen `type: playbook` notes (how we run it) plus dated `type: event_instance` notes (a specific occurrence). Every instance links its parent playbook.
- **`wiki/organization/`** — team roles, structure, the Church Mobilization Pathway, endorsement and assessment processes.
- **`wiki/indexes/`** — generated by the sync scripts. Never hand-edit.
- **`wiki/templates/`** — start-here templates for people, churches, and events.

## Note types

`person` (with `person_type` planter / pastor / staff / association_leader / partner), `church`, `playbook`, `event_instance`, `group`.

## The Church Mobilization Pathway

Churches move along five levels: **1 Cooperating, 2 Supporting, 3 Sending, 4 Multiplying, 5 Movement.** Set `mobilization_level` from evidence, not optimism: a church actively sending a planter is demonstrably Level 3. See `wiki/organization/Send KC Church Mobilization Pathway.md` for the full pathway.

## Sync scripts

Run these from the vault root:

- `python3 scripts/sync_send_network.py` rebuilds the People, Pipeline, Groups, Events, Churches, and Pastors indexes in `wiki/indexes/`, and refreshes pathway group member tables.
- `python3 scripts/sync_tasks.py` rebuilds the Task Index and owner task roll-ups from vault-authored tasks only.
- `python3 scripts/sync_sendnetwork_dashboard.py` runs both of the above as the normal dashboard refresh.

## Ownership posture

The vault should help the team see responsibility clearly. Do not assign every task to one person by default. If the city lead owns a funding decision, they are the task owner. If a CPC owns planter follow-up, that CPC is the task owner. If ownership is unknown, capture the context as a plain bullet and ask.

## Tasks

A checkbox is one real, owned task in this exact form: `- [ ] {priority?} [[Owner]] about [[Subject]] :: what to do ^t-id`. The owner is a wikilink to a real person note in this vault. Operational, SOP, and reference lines use plain bullets `* `, never checkboxes. After adding or completing tasks, run `python3 scripts/sync_tasks.py`. Full grammar is in `skills/task-setup.md`.

## Care rules (this is a shared vault)

1. **Add, don't overwrite.** Extend notes and preserve what's there. Never wholesale-rewrite a roster, church, or someone else's content unless they ask.
2. **Don't change the architecture.** Folder structure, frontmatter schema, sync scripts, and skills are the shared framework. Add and maintain content; don't redesign the system. If something looks misfiled, flag it.
3. **Handle sensitive material with discretion.** Some notes hold sensitive information: a candidate's legal or immigration details, funding, or a candid read on a person. Don't widen the audience of sensitive information beyond what is intended, and never paste a person's legal or financial details into a wider communication or a public AI tool.
4. **Never hand-edit generated sections** (between `<!-- START ... -->` and `<!-- END ... -->`) or the files in `wiki/indexes/`.
5. **Never send a message** (email or text) on anyone's behalf without asking first and getting explicit approval.
6. **Never delete or bulk-move notes** on your own. If you find a duplicate or a problem, report it and ask.

## Email & text formatting

When writing a draft email or text, put the final copy-pasteable text in a plain ` ```text ` code block so it can be copied cleanly, write out raw full URLs (not markdown links), and avoid `**bold**`/`_italics_` inside the block so the copied text looks hand-typed.
