## Scroll jump fix, 2026-11-03

Dave saw the page jump down when tapping Next in the Make Space widget. Two causes in the widget: its height changed with caption length, and the camera updated the SVG viewBox about 60 times a second, so the host's MutationObserver re-measured the iframe (collapsing it to 0px and restoring) on every animation frame, which is a known trigger for scroll jumps in iPhone Safari. Fix inside the widget only: the camera is now one CSS transform transition on a world group (one DOM change per tap), and the caption area is sized to the longest caption at the current width so the widget height never changes. Verified in Chromium at 375, 390 and 1280 px: one iframe height per width and one observer callback per tap. Not verified on a real iPhone.

## Scroll jump, root cause and host fix, 2026-11-03

Dave narrowed it down: the page jumps only when the widget's top is scrolled above the screen. Reproduced in Chromium: clicking Next moved the page about 650 px (one widget height). Cause: the host's `applyHeight` in `scripts/widget-iframe.js` collapses the iframe to 0px to re-measure it, and browser scroll anchoring shifts the page during that collapse. Turning off `overflow-anchor` page-wide removed the jump. Fix in `widget-iframe.js`: pause scroll anchoring on the host page (html and body `overflow-anchor: none`) during the measurement and resume it two animation frames later, without touching the scroll position. A first attempt that restored the scroll position after measuring fixed the jump but could cut off smooth scrolls already underway, so it was replaced. Verified with real mouse clicks at 1280x800, 1280x600 and 390x844 with the widget top 0 to 450 px above the screen: 0 px page movement in every case. This applies to every lesson widget.
