## Changes and decisions

The restore review showed raw keys such as `answers:question-101-5-key`, the words "stores" and "version 1", and "1 questions." It now names each item by course, lesson and question, for example "Starting in Discipleship 5: The Church. Question: 5.3 - What encourages you about the Aspen Grove picture...".

Saved answer IDs do not reliably name their lesson (202-05 keeps `201-09-*` IDs, 203-08 keeps `301-08-*`), so labels come from `data/meta/answer-index.json`, generated from the lesson files by `scripts/build_answer_index.js`. `test_backup_labels.js` fails if that file drifts from the lessons, so any lesson that adds or rewords questions must rerun the builder. A key not in the index, such as a retired shared key, is labeled as an older saved answer and never assigned a guessed lesson. Internal keys show as "App housekeeping setting"; unrecognized keys stay visible with their raw name so nothing is hidden. The index lives in `data/meta/` because foundation QA requires exactly 47 JSON files in `data/`.

Messages in the preview and restore helpers were rewritten in plain language (differences, items, saved data on this device) with correct plurals. The partial-file conflict line no longer says "proposed default: keep current device value," which contradicted the no-preselection rule. No restore logic, key, stored value, safeguard or button behavior changed; every label is rendered with `textContent`.
