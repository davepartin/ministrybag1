## Changes and decisions

Confirmed restore sits on top of the ENG-006b preview. Only an exact version 1 file that passes the current validator can reach confirmation. Partial source backups stay preview-only.

Conflict review requires an explicit keep-device or use-backup choice for every disagreement, including differing retained ambiguity items. Nothing is preselected. Backup-only keys are added, device-only keys stay, matching values stay, unknown keys stay stored keys, and ambiguous answers stay unassigned.

Before any write, the page builds and triggers a versioned safety backup of current in-memory and device state, including unsaved edits and captured original raw evidence. Restore stays disabled until that download is started and the learner acknowledges it. The page does not claim the browser proved the file was saved.

Confirmation is bound to a fingerprint of the exact file plus current in-memory values, storage raw strings, load reasons and write guards. File change, answer edit, navigation, a new preview, a storage event or a guard/status change makes confirmation stale and requires a fresh preview. A cancel, stale confirmation or failed write leaves original raw bytes, memory and guards unchanged.

The three stores are one transaction. A complete pre-write snapshot is kept. If any write or verification read fails, already-changed stores roll back. If rollback is incomplete, per-store errors stay visible and the pre-restore safety download is offered. Success is never reported in that case. In-memory state and UI update only after every write verifies.

Failed-load guards clear only after their original raw evidence is in the safety download and the confirmed replacement verifies. Restore errors stay visible. Success shows exact restored, kept and conflict counts without a persistent green save banner.
